Using Stupen

Stupen plans what to practise, builds exercises it has already solved and coaches you up to a help limit you choose. It is not released: it runs on SUBCULT's homelab for invited learners. These docs describe that running app.

Getting started

  1. Sign in. Stupen sits behind SUBCULT's sign-in; each person gets their own tracks, prompts and history.
  2. Create a track: the subject in your words, your level (brand new, beginner, intermediate, advanced or expert), your goals, your background, how you like to learn and how long a session is.
  3. Pick a practice format (see Practice formats). Stupen guesses one from the subject; React, for example, suggests the React container.
  4. Add materials you already have, if any, and choose whether to write the plan now or to search the web for good material first.
  5. Open the first lesson, work in the editor, run the checks and ask the coach when you need it.

The help limit

You choose how much the coach may help, from 0 to 6. It stays under your limit and labels each reply with the level it used. The default depends on your level and can be changed for each lesson.

LevelNameThe coach…
0Questions onlyasks what you think, tried or saw
1Pointnames the idea, or the part of the work or output to look at
2Explainexplains the idea or the error message in general terms
3Diagnosesays what is wrong in your work, not how to fix it
4Directdescribes the fix or approach in words or pseudocode
5Fragmentshows a few lines that don't finish the task
6Solvegives a full worked solution; the attempt is closed

The limit is an instruction to the coach, which is a language model and can be wrong. If a useful answer needs a higher level, it says so and asks you to raise the limit.

Plans

The plan sets the order, scope and pace of your lessons; each lesson is built when you reach it. You can:

  • Revise it with an instruction, such as "go slower", "add a small project" or "prepare me for interviews".
  • Adapt it to your progress: the coach re-plans the remaining lessons from how the finished ones went.
  • Edit it yourself as Markdown.
  • Restore an earlier version: every change keeps the previous plan.

The coach keeps short progress notes about you, which later lessons and replies use. You can read and edit them on the plan page.

Lessons and checks

A lesson has a brief, starter files, tests or a written task, escalating hints and, often, a reading list. Before you see it, its hidden reference solution must pass the tests and the starter files must fail them. If that check still fails after one retry, the lesson is kept and marked tests unverified.

  • Run checks saves your files and runs the tests in a fresh, isolated copy of the lesson, so code cannot change its own tests.
  • Hints open one at a time in the brief.
  • Add a file with + next to the tabs. Test files stay read-only.
  • Preview builds web lessons and shows them in an isolated frame that can't reach the app.
  • Written answers are handed in with Submit for grading; the coach records pass or revise.

Practice formats

Quick, no packages

Python, TypeScript, JavaScript, Go, Rust, Java, C, C++, SQL (SQLite) and Bash, using the standard library, in a sandbox with no network. Checks start at once.

Written answers

For any subject without a test runner: concepts, design, maths, natural languages. You answer in a Markdown file and the coach grades it against the brief.

Your own check command

For another language installed on the server: you give the shell command that checks a lesson folder.

Container

Real projects with any packages. See Containers.

Containers

Thirteen ready-made environments: React with Vite, a plain web page, Node, Python, Go, Rust, Java with Maven, Ruby, PHP with Composer, C# and .NET, Elixir, Deno and Bun. A custom environment can use any Docker image with your own setup, install, check and preview commands.

  • Packages install from the internet when a manifest such as package.json or requirements.txt changes, and stay cached for the lesson. You can edit the manifest to add a package.
  • Checks run offline unless the environment allows network (the .NET environment does).
  • Containers run with limited memory and CPU, and their network reaches the public internet only, never the network Stupen runs on.

Materials

Add what you learn from: a link, an upload (PDF, Markdown, text, Word, ODT, EPUB, HTML, notebooks or code) or pasted text. Or let the coach search the web and save what it finds. Then build materials into your plan, make a lesson from them, or attach one to a question in the chat. Pages that need JavaScript are rendered before their text is saved.

Prompts

The buttons above the chat come from your prompt library. There are thirteen to start: Explain the idea first, Give me a hint, Explain the failure, I'm stuck, Review my solution, Grade my answer, Explain the selection, Explain it more simply, Show another example, Quiz me, Go deeper, Where is this used? and What should I practise next?

Edit them, add your own and reorder them on the Prompts page. A prompt can use placeholders such as {{selection}} for text selected in the editor or {{failing}} for the failing check output. Any prompt can have a trigger:

TriggerFires
Only when I pick itnever on its own
When I open a lesson for the first timeonce per lesson
When my checks failafter a failing run
When my checks fail three times in a rowon every third failure in a row
When my checks passthe first time a lesson passes
When I submit a written answeron Submit for grading

Each triggered prompt either sends automatically or is suggested above the message box. Switch automatic prompts off in the coach panel at any time.

Undo and recovery

  • Reset file puts a lesson file back to its starter code.
  • Earlier versions on the plan page restores any previous plan; the current one is kept.
  • Files you added to a lesson can be deleted; files that came with the lesson can only be reset.
  • Solution shows the reference solution after you confirm. It closes the attempt and the lesson shows that you viewed it.

Limits

  • Stupen is not released and has no public sign-up or download. The source is public, and the README explains how to run your own copy.
  • The coach is a language model and can be wrong, about the subject and about the help level it reports.
  • Generated lessons can contain mistakes even when verified; tell the coach when a test looks wrong.
  • Quick formats use the standard library only. Use a container format for packages.
